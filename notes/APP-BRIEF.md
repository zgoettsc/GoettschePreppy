# App brief (app workers A1, A2, A3)

GoettschePreppy turns a household profile into ONE offline HTML file: the household's survival
binder. Read `docs/00-decisions.md`, `docs/01-architecture.md`, `docs/02-profile-schema.md`,
`docs/07-sources-and-fetch.md`, `docs/09-authoring-spec.md`, `NOTICE-TO-USERS.md`,
`schema/profile.schema.json`, `schema/context.json`, `schema/page.schema.json`. Load the
`claude-api` skill before writing any code that calls Claude.

Kit repo: `/home/user/goettschepreppy` (write only your own files, listed below; do not run git).
Household binder for reference code: `/home/user/SHTF` (read only). Its `scripts/build-app.mjs`,
`scripts/lib.mjs`, `scripts/render.mjs`, `scripts/build-volumes.mjs` and `app/shtf-binder.html`
are the proven offline single-file app, PDF and volume builders; reuse their ideas and code.

## Hard requirements
- **Never store user answers.** No server-side storage, logs, analytics, cookies. Browser memory
  only, plus `profile.json` if the user chooses to download it. The never-stored notice appears on
  every settings step and on the download screen (text in `NOTICE-TO-USERS.md`).
- **No links in the binder.** The generated file contains no external URL at all (test for it).
- **Offline binder.** The output HTML opens from a phone's Files app with airplane mode on; readable
  without JavaScript (static HTML body), upgraded by JS where it runs (search, region picker,
  condition picker, photo slots, PDF export via print CSS). Dark default, battery-frugal.
- **Two sizes** (G11): Small = pages, plates, figures, PD/open sources bundled with the kit are NOT
  included (citations only); Large = plus every cited source document (PD/open from the kit's own
  static assets; restricted/blocked fetched through the relay per household), plus USGS topo maps
  (G16). Show both sizes before generating; Small can upgrade to Large later from profile.json.
- **Model**: `claude-opus-5-5` throughout (G19). Streaming. No Batch API (retention = storage).
- **Hosting**: Cloudflare Pages (static) + one Cloudflare Worker relay (G12). Free `pages.dev`.
- **Access keys**: one per friend, stored as SHA-256 hashes in a Worker secret (G18).
- **Regenerate** from an uploaded profile.json (G22).

## Interfaces (so the three of you can work in parallel)

### Relay (A1) — `worker/`
- `POST /api/v1/check` `{access_key}` → `200 {ok:true,label}` or `401`.
- `POST /api/v1/messages` `{access_key, request}` where `request` is a Messages API body. Relay
  checks the key, enforces `model == "claude-opus-5-5"`, caps `max_tokens` (env `MAX_TOKENS`,
  default 32000), forwards to the Anthropic API with the owner key, and streams the SSE response
  back unchanged. No logging of bodies.
- `POST /api/v1/fetch` `{access_key, source_key}` → looks the key up in `sources/index.json`
  bundled into the Worker at build time (keys and URLs only), fetches, streams bytes with the
  upstream content-type. Only hosts in the index. Size cap (env `FETCH_MAX_MB`, default 60).
- `POST /api/v1/fetch-map` `{access_key, url}` → only USGS hosts in an allowlist; for topo maps.
- Per-key request counter in Workers KV (binding `COUNTS`, optional): the only state kept.
- CORS restricted to env `PAGES_ORIGIN`.
- Secrets: `ANTHROPIC_API_KEY`, `ACCESS_KEYS` (JSON array of `{label, sha256}`).
- `scripts/make-access-key.mjs` prints a new random key (to give a friend) and its JSON entry.
- `docs/10-deploy.md`: exact owner steps (Cloudflare account, wrangler login, secrets, deploy
  Worker, deploy Pages, add a friend, revoke a friend). The owner has never used Cloudflare.
- Tests: `worker/test/*.mjs` run with plain node against the exported handler with a mocked
  upstream `fetch` (no network, no real key). `npm run test:worker`.

### Settings page (A2) — `app/settings/`
- Static `index.html` + JS modules + CSS; no framework required; no CDN at runtime (vendor what you
  need into the repo). Steps 0 to 8 exactly as `docs/02-profile-schema.md`. County pickers read
  `app/build/regions-lite.json` (state → counties) built by A3 from `data/regions/` (if absent,
  free-text county with a warning).
- Decision-card step reads card pages' `options` and `settings_summary` from `app/build/kit.json`
  (built by A3). Until cards exist, use a fixture `app/settings/fixtures/cards.json` from the docs/05
  table.
- Validates against `schema/profile.schema.json` via an ajv standalone validator generated by
  `scripts/build-settings.mjs` into `app/settings/profile-validate.js`.
- Save / load `profile.json`. Access key checked via the relay before generation.
- Generate screen: Small or Large with estimated sizes, progress, cancel, then download. Calls
  `generateBinder()` from `app/lib/generate.js` (A3).
- Accessibility: works on a phone at 375 px; large tap targets; plain words.

### Generator and binder (A3) — `app/lib/`, `app/binder/`, `scripts/build-kit.mjs`
- `scripts/build-kit.mjs`: reads `content/sections/**`, `sources/index.json` (without URLs),
  `data/regions/` (when present), `images/` plates, `figures/` → `app/build/kit.json` (pages as
  template Markdown + frontmatter, cards with options, source metadata, region data, plate and
  figure assets) and `app/build/regions-lite.json`. Also generates the section intros, master
  index, binder map, bibliography (title, publisher, date; no URLs) as `generated` pages.
  Copies kit-shipped PD/open source files to `app/build/sources/` for Large downloads.
- `app/lib/context.js` + `app/lib/derive.js`: profile + region data → the context object exactly as
  `schema/context.json` (values, flags, lists; derived formulas documented there).
- `app/lib/template.js`: the template syntax in `docs/09-authoring-spec.md` section 4, nothing more.
  Missing values render a fill-in blank. Unit-tested.
- `app/lib/generate.js`: `generateBinder(profile, kit, {relay, size, onProgress, signal})` →
  `Blob`. Steps: context → render every page → `{{ai}}` blocks via relay (spec files in
  `content/ai-blocks/`) → review passes via relay (structured outputs: a JSON findings list;
  mechanical fixes applied, the rest listed on a generated "Review notes" page) plus local checks
  (no URLs, no owner tokens, no unfilled required slots) → assemble the binder HTML from
  `app/binder/` shell with everything inline (plates/figures as data URIs) → for Large, fetch
  sources (kit static assets for PD/open; relay for restricted/blocked) and bind behind citing
  pages; failures listed on "Sources not captured". Every page gets the "AI-reviewed, not
  human-verified" stamp. A dry-run relay (canned responses) for tests.
- `app/binder/`: the offline shell (adapt SHTF `build-app.mjs`): TOC, search, cross-reference
  links for `→ NN-MM`, emergency row, region picker for Section 32, condition picker for Section 02,
  photo slots (attach a photo in the browser, then "Save a new copy" downloads the HTML with the
  photo embedded; nothing uploaded), private-copy notice on page two, PDF export via print CSS with
  sources behind each tab.
- `scripts/test-generate.mjs`: generate from `tests/profiles/*.json` with the dry-run relay into
  `build/`, then a Playwright smoke test (Chromium is preinstalled: `require('playwright')` works;
  do not install browsers) that opens the file offline and checks search, a cross-reference, the
  notice, and zero external URLs.
