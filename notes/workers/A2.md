# A2: settings page (`app/settings/`)

## What I built

A static walkthrough for steps 0 to 8 of `docs/02-profile-schema.md`, plus a final "Make your binder"
screen. Plain ES modules and CSS. No framework, no CDN, no fonts fetched, and a strict CSP meta
(`connect-src 'self' https:` so the relay can be on a `workers.dev` address).

| File | Role |
|---|---|
| `index.html`, `settings.css` | Shell. Dark and light themes (follows the system; a Theme button cycles Auto, Dark, Light and is not remembered). 375 px layout, 44 to 48 px tap targets, skip link, visible focus. |
| `app.js` | Step navigation, error summary, Save / Load, the access-key check, the opt-in keep toggle, the Generate screen (Small or Large with estimates, progress bar, Cancel, Download). |
| `steps.js` | Every question in steps 0 to 8, each with a plain-words "Why we ask" line. Add-and-remove lists for members, vehicles, medicines, allergies, pets, livestock, destinations, local contacts, power stations, panels, heaters and water filters. County picker. Condition picker (CL-01 to CL-26, names from docs/04). Decision-card step. Privacy section showing the relay code. |
| `state.js` | Answers in memory only. `toProfile()` cleans the draft into a schema profile (drops empty answers, drops hidden follow-ups, fills every DC-01 to DC-24 with an option or `undecided`). `loadProfile()` accepts partial or odd files without crashing. `validate()` turns ajv errors into plain words, keyed to the step and the field. |
| `ui.js` | Question widgets (text, number, select, radio, yes/no/skip, multi, checkbox) and the list widget. |
| `data.js` | Enums with plain labels, states, conditions. |
| `loaders.js` | `app/build/regions-lite.json` (tolerates `{XX:[...]}` or `{XX:{name,counties:[...]}}`, counties as strings or `{name}`). `app/build/kit.json` cards from `kit.cards` or `kit.pages` (front matter `card`, `options`, `settings_summary`). Falls back to `fixtures/cards.json`. Size estimates from `kit.sizes` (or `size_estimates`), else `config.js` (G11 ranges). |
| `relay.js` | `POST {relayBase}/api/v1/check {access_key}`: 200 accepted (shows the label), 401 not accepted, 403 means the relay refused this page's origin (PAGES_ORIGIN), anything else counts as unreachable. |
| `generate-adapter.js` | Imports `generateBinder` from `app/lib/generate.js` at run time and calls `generateBinder(profile, kit, {relay, size, onProgress, signal})`, with `relay` set to the base-URL string. If that module is missing, a clearly marked STUB makes a placeholder file and the Generate screen shows a test-mode banner. |
| `storage.js` | The only use of browser storage: the opt-in "Keep my answers in this browser" toggle. It is off by default and says what it does. It never stores the access key, and turning it off erases what it kept. |
| `config.js` | **The owner sets `relayBase` here** (the Worker address, no trailing slash). `?relay=https://...` overrides it for testing. `?dryrun=1` switches to test mode: A3's fake relay (`app/lib/relay-dryrun.js`) runs inside the tab, nothing goes over the network, and banners say so. |
| `fixtures/cards.json` | 24 cards from docs/05 part C, each with a short summary of my own and option ids exactly as in that table. It is used only when kit.json has no card pages (A3's kit does have them now). |
| Generated: `profile-validate.js`, `notice.js`, `relay-source.js` | Written by `scripts/build-settings.mjs` (`npm run build:settings`): an ajv standalone validator with ajv's two runtime helpers inlined so it runs in the browser, the notice text taken word for word from `NOTICE-TO-USERS.md`, and the relay code from `worker/src/*.js` for the privacy section (G13). **Rerun after any change to the schema, the notice or the Worker.** |
| `tests/walkthrough.mjs` | Playwright test (`node app/settings/tests/walkthrough.mjs`). |

Notices: every step shows "Your answers are never stored". Step 0 shows it in full. Steps 1 to 8 show
the heading and first paragraph, with the second paragraph ("When you press Generate…") behind a
disclosure to save scrolling on a phone. The Generate screen shows the never-stored notice and the
private-copy notice in full. Step 0 also shows the private-copy notice and "What this binder is".

Schema additions from the coordinator are in: `medications[].days_on_hand`, `dwelling.roof_area_sqft`,
`gear.generator.volts`, `destinations[].water_source` and `destinations[].sewer`. The validator has
been rebuilt.

## How to run

- `npm run build:settings` regenerates the three generated files.
- Serve the repository root statically (ES modules do not load from `file://`) and open `/app/settings/`.
  The page expects `../build/` and `../lib/` next to it, so deploy `app/` as the Pages root.
- `node app/settings/tests/walkthrough.mjs` runs 27 checks. Scenario A: the kit is unbuilt (forced
  404s). It walks every step with a two-person household, checks plain-words errors, the notices, no
  horizontal scroll and tap targets of at least 44 px at 375 px, the key check (wrong key, then
  right key), add and remove, then saves `profile.json` and validates it with ajv against the
  schema. It then runs the stub generator with progress, download and Cancel, confirms storage and
  cookies are empty, reloads, loads the saved file and checks it re-exports byte-identical, checks a
  junk file is rejected, a partial file loads with its gaps marked, and the keep toggle works.
  Scenario B: kit, regions and generator are mocked. It checks that county pickers become lists,
  that cards come from the kit, and the exact `generateBinder` arguments. Scenario C: the real
  built kit and A3's real `generate.js` with `?dryrun=1`. It produces a real Small binder with no
  request leaving the machine. Screenshots go to `build/settings-shots/`, outputs to
  `build/settings-test/`.

## Decisions and questions

- **Access key in profile.json.** The schema requires `access.access_key`, so by default the saved
  file includes it, with a warning to keep the file private. The Generate screen has an "Include my
  access key" checkbox (default on). A file without a key still loads; the person types the key again.
- **Saving incomplete answers is allowed**, so people can finish later. Loading a file that fails the
  schema loads what fits and marks the gaps in each step.
- **DC-05** appears only when `attached_garage` is yes; otherwise it is recorded as `undecided` (docs/02).
- Worksheet cards (DC-12, 19, 24): A3's kit gives them one option (`worksheet`). The fixture gives none,
  and the page then shows the card as text and records `undecided`.
- `regions-lite.json` currently has empty county lists, so county is free text with a warning. When
  counties arrive, it becomes a list automatically, and a loaded county that is not in the list is
  flagged.
- A `beforeunload` prompt fires while a generation is running, or when there are unsaved answers and
  the keep toggle is off.
- `window.__settings` exposes helpers for tests and the console. It only reads what is on screen.
- `app/settings/tests/` ships with `app/` if the owner deploys the whole folder. It is harmless, but
  can be excluded.
- I did not run git and did not touch `.gitignore` (`build/` is already ignored).
