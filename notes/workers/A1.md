# A1: Relay (Cloudflare Worker)

## What I built

| File | What |
|---|---|
| `worker/src/index.js` | Worker entry point. Exports only `default { fetch }` (the Workers runtime treats every named export of the entry module as an entrypoint; exporting constants from it crashes `wrangler dev`, found and fixed). |
| `worker/src/relay.js` | All logic. `makeHandler({fetch, sourceUrls})` for tests; helpers exported for tests. |
| `worker/src/source-urls.json` | Generated `{key: url}` (406 sources today). Built by `scripts/build-worker-index.mjs`. |
| `worker/test/relay.test.mjs`, `worker/test/fetch.test.mjs`, `worker/test/_util.mjs` | 53 tests, plain `node --test`, mocked upstream fetch, fake key, no network. |
| `wrangler.toml` | Repo root. `main = worker/src/index.js`, KV binding `COUNTS` (placeholder id), `[vars]` with `PAGES_ORIGIN` placeholder and caps, Workers Logs off. No secrets. |
| `scripts/build-worker-index.mjs` | `sources/index.json` + `sources/additions/*.json` (array or `{sources:[...]}`) to `worker/src/source-urls.json`; skips non-http(s), IP hosts, ports, credentials; index wins on key conflicts; `--check` for CI. |
| `scripts/make-access-key.mjs` | New key (`gpk_` + 32 random bytes base64url) + `{label, sha256}` entry; keeps a hashes-only list in `access-keys.local.json`; `--list`, `--remove <label>`, `--hash <key>`, `--print-only`, `--file`. |
| `docs/10-deploy.md` | Owner guide from zero: account, `npx wrangler@4` login, KV, Pages project, `PAGES_ORIGIN`, tests, deploy, secrets, health check, `relayBase` in `app/settings/config.js`, Pages deploy of `app/`, add/revoke friend, rotate API key, counts, updates, limits, USGS map hosts, privacy, troubleshooting. |
| `package.json` | Added only `"test:worker"`. |

## How to run

```sh
npm run test:worker          # rebuilds source-urls.json, then node --test worker/test/*.test.mjs
```

Also verified (not deployed): `wrangler deploy --dry-run` bundles it (69 KiB), and `wrangler dev`
locally (workerd) answered health, check, CORS refusal, 413, model refusal, and a real fetch-map of
a USGS thumbnail from `prd-tnm.s3.amazonaws.com`.

## Interface as built (for A2 and A3)

All errors: `{type:"error", error:{type, message, upstream_status?}}`. Relay types: `invalid_request`
400, `unauthorized` 401, `forbidden` 403 (origin or host), `not_found` 404, `method_not_allowed` 405,
`payload_too_large` 413, `not_configured` 500/502, `upstream_error` 502.

- `POST /api/v1/check {access_key}` -> `200 {ok:true,label}` | 401. Not counted.
- `POST /api/v1/messages {access_key, request, betas?}`
  - `request.model` must be `claude-opus-5-5`; `max_tokens` > `MAX_TOKENS` (32000) is lowered and the
    response carries `x-relay-max-tokens: 32000`.
  - Upstream: `POST https://api.anthropic.com/v1/messages`, `anthropic-version: 2026-10-21`
    (override with var `ANTHROPIC_VERSION`). **A3: on 2026-10-21 `temperature`, `top_p`, `top_k`
    are a 400 on every model; do not send them.**
  - Betas: `betas: [...]` in the JSON body and/or an `anthropic-beta` request header (allowed in
    CORS); merged, validated, sent as `anthropic-beta`.
  - Body forwarded as `JSON.stringify(request)` of the parsed body: same key order, every field
    (`cache_control` included), so prompt caching is unaffected. `access_key` is never forwarded.
  - Refused: `thread`, `mcp_servers`, `container`, `speed:"fast"` (unless `ALLOW_FAST_MODE=1`),
    `fallbacks:"default"`, and fallbacks naming models other than `claude-opus-5`,
    `claude-opus-4-8` (`FALLBACK_MODELS` var). A3: if you want refusal fallbacks (the claude-api
    skill recommends them for Opus 5.5; the medical/firearms pages may hit the `bio` classifier),
    send `betas:["server-side-fallback-2026-07-01"]` and `fallbacks:[{model:"claude-opus-4-8"}]`.
    Note that this means a refused page is written by another model, which bends G19; owner call.
  - Response: upstream status and body bytes unchanged (SSE or JSON; 400/413/429/500/529 bodies are
    the provider's own error JSON). Headers passed: `content-type`, `request-id`, `retry-after`,
    `x-should-retry`. Upstream 401/403 (owner key bad) becomes a generic 502 `not_configured`.
  - Body cap `MAX_BODY_MB` (8).
- `POST /api/v1/fetch {access_key, source_key}` -> bytes with upstream `content-type` (or
  `application/octet-stream`), `content-length` when known. Unknown key 404. Up to 3 redirects,
  http(s) only, default ports only, no credentials, no IP-literal private/loopback/link-local/CGNAT,
  no IPv6 literals, no `localhost`/`.local`/`.internal`/dotless hosts. Redirects may leave the
  index's host (CDNs), but every hop is checked. Upstream non-2xx -> 502 with `upstream_status`
  (A3: use it for "Sources not captured"). Cap `FETCH_MAX_MB` (60): 413 if declared larger; a
  stream without length errors mid-stream when it passes the cap.
- `POST /api/v1/fetch-map {access_key, url}` -> https only, hosts and path prefixes:
  `prd-tnm.s3.amazonaws.com/StagedProducts/`, `prd-tnm.s3.us-west-2.amazonaws.com/StagedProducts/`,
  `tnmaccess.nationalmap.gov/api/v1/` (TNM Access API, so A3 can search maps by bbox through the
  relay), `rockyweb.usgs.gov/vdelivery/`. Every redirect re-checked. Cap `MAP_MAX_MB` (100; US Topo
  GeoPDFs are about 20 to 60 MB, the one I sampled was 27.7 MB).
- `GET /api/v1/health` -> `{ok, configured:{anthropic_api_key, access_keys, counts, pages_origin, sources}}`
  (booleans and counts only).
- CORS: `PAGES_ORIGIN` (comma list allowed; trailing slash ignored). A request with another Origin
  gets 403. A request with no Origin header (scripts) is allowed without CORS headers; the access key
  is the real gate.
- Counter: KV key `count:<YYYY-MM>:<label>:<hash8>`, integer string, bumped for messages, fetch,
  fetch-map (not check), via `ctx.waitUntil`; a KV failure never fails a request.

## What the owner must do

Follow `docs/10-deploy.md`. In short: Cloudflare account; `npx wrangler@4 login`; create KV and paste
its id into `wrangler.toml`; create the Pages project and set `PAGES_ORIGIN`; `npm run test:worker`;
`npx wrangler@4 deploy`; `secret put ANTHROPIC_API_KEY`; make keys and `secret put ACCESS_KEYS <
access-keys.local.json`; set `relayBase` in `app/settings/config.js`; build and
`npx wrangler@4 pages deploy app`. Set a spend limit in the Claude Console. Rerun the worker build and
deploy whenever the source index changes.

## Open points and questions

1. **Free-plan limits.** Workers Free gives 10 ms CPU per request; parsing and re-serialising a
   1.1 MB Messages body took about 5 ms in Node. A large cached template corpus per request could hit
   error 1102. Workers Free also allows only 1,000 KV writes a day, about two full binders of
   counting. The deploy doc tells the owner to move to Workers Paid ($5/month) if either shows up.
   A3: keep per-request bodies as small as the design allows.
2. **Pages 25 MiB per-file limit.** `app/build/kit.json` and any kit-shipped PD/open source file in
   `app/build/sources/` must each stay under 25 MiB, or the Pages upload fails (A3).
3. **No URLs in the binder.** `worker/src/source-urls.json` and the relay source contain URLs. If
   the privacy page shows the relay source (G13), show it on the settings site, not inside the
   binder, or the binder's zero-URL test fails (A3).
4. **`access-keys.local.json`** holds hashes only but should not be committed; `.gitignore` is not
   mine to edit. Coordinator: consider adding it.
5. **Notice wording.** NOTICE-TO-USERS says the relay "keeps a count of requests and nothing else".
   True of the code. Cloudflare keeps its own aggregate request metrics (counts, status, country)
   for any Worker; the deploy doc says so. Owner may want one sentence in the notice.
6. Settings site path: Pages serves `app/`, so the page is at `/settings/`. If A2 or A3 adds an
   `app/index.html` redirect, the root address works too.
