# Owner decisions that bound the design

Decisions made by the owner in the 2026-11-16 discussion, in the order they were made. Each one is
binding for the design documents in this folder. "G" numbers are the kit's decision register, kept
separate from the household binder's C and D numbers.

| # | Decision | Consequence for the kit |
|---|---|---|
| G1 | **US only, all states always included.** Users pick a home base in settings; the binder still carries every state's region data because a household may have to cross the country. | A national region appendix (climate, hazards, plants, trees, NWS offices and SAME codes, state contacts) is in every binder. The home base is promoted to the front; the rest sits behind a region picker in the app. |
| G2 | **Owner hosts and pays. A limited set of friends gets a link and an access key.** | Static settings page plus a stateless relay function holding the owner's API key. Access keys are checked by hash; no user accounts. Cost is the owner's. No "bring your own key" mode is needed for launch (keep it as a hidden option). |
| G3 | **Medical: condition library at WebMD level, no doctor visit required.** Users tick common conditions in settings; the binder adds the matching modules. The whole library stays in the app so a condition can be added later. No derived dosing; published tables printed as published; a "my meds" table the household fills from its own bottles. | `docs/04-condition-library.md`. The household binder's T1D and anaphylaxis sections seed two modules and lose their physician-signed rules. |
| G4 | **Decision cards for every risk trade-off, written for people new to prepping.** Explain the hazard, why the manufacturer or agency set the rule, the risk, the mitigations, the options; let the household choose its risk tolerance. Do not assume they know what kerosene, diesel or gasoline are. | `docs/05-decision-cards.md` and `docs/06-explainers.md`. The owner's own risk acceptances are never defaults. |
| G5 | **App only.** The owner has no printed binder and envisions the kit as an app. The PDF export button stays because the pipeline exists. Plants for all regions always accessible in the app. | Output is one HTML file (same renderer family as the household binder's phone app), with offline-install and charge-discipline guidance up front. |
| G6 | **No human review. AI reviews everything.** Only family-specific things need human input (where things are, supply checklists). | Automated review passes (source trace, consistency, slot validation, leftover-personal-token scan) run on every generated binder. Every page carries an "AI-reviewed, not human-verified" stamp. The disclaimer says so in plain words. Known limit recorded: correlated error, where every public source is wrong the same way, is not caught by AI review. |
| G7 | **Licence: owner defers.** Name is GoettschePreppy for now. Owner wants no or limited legal exposure if a friend shares it elsewhere. | Code MIT, content CC BY-NC-SA 4.0, disclaimer first page, AI-reviewed stamp, decision cards place risk choices with the household, access keys limit distribution. Whether to put an entity between the owner and the hosting is a question for the owner's lawyer. |
| G8 | **No links anywhere. The app is the SHTF reference and must contain everything; there is no internet to look things up.** | Rendered pages never print a URL. Sources are cited by title, publisher and date, and the full source document is bound inside the app behind the page that cites it. URLs exist only in the kit's source index, used at fetch time. |
| G9 | **Copyright in SHTF is not the owner's concern; users are told they cannot share their copy because sharing breaks copyright. Non-redistributable sources are fetched for each user when they download.** | `docs/07-sources-and-fetch.md`. The public kit ships only owner text and public-domain works. At download time the user's build fetches every other cited document into their private copy through the stateless relay. The private-copy notice (`NOTICE-TO-USERS.md`) is shown in settings, at download, and on page two of the binder. |
| G10 | **New repository**, not a branch of the household binder. | This repository. The household binder stays private and becomes the first test profile: the kit must regenerate something close to it from a profile. |

## Decisions still open

| # | Question | Default if unanswered |
|---|---|---|
| O1 | Maps. Does the app embed map imagery for the home base, destinations and routes? Public-domain USGS topo tiles for a whole route are large (hundreds of MB) and need a fetch at download; without them the maps page is a list of which paper maps to buy. | Ship the paper-map list; offer an optional "fetch USGS quads for my home county and destinations" step at download, size shown first. |
| O2 | Firearms content. Include the security section's firearms pages for every household, or only when "firearms owned" is ticked? | Include always (the owner's principle: the binder has everything); gate only the inventory and armorer templates on ownership. |
| O3 | Access-key policy. One key per friend, revocable, or one shared key? | One key per friend, stored as a hash in the relay's configuration, revocable by removing the hash. Count per key is the only thing logged. |
| O4 | Regeneration. Can a household come back and regenerate after a life change (new baby, new condition) without re-entering everything? | Yes, from the profile file they chose to save on their own device. Nothing server-side. |
| O5 | Plant plates for all regions: roughly 300 to 400 species nationally with 3 photographs each. Fetch and licence-check now (slow, owner cost once) or at download (slow per user)? | Fetch and licence-check once into the kit; USDA and Forest Service photographs are public domain and may be redistributed. |
| O6 | Model choice for generation. Opus-class for the household pages and review passes; Sonnet-class for slot filling? | Opus-class everywhere for launch; optimise cost after the pilot. |
